## Возможности

/start отправляет приложенный баннер и приветствие. Инлайн-меню: заказ, переписка, услуги, документы, сайт и представитель. Перед обращением запрашивается отдельное явное согласие; само начало общения не считается согласием. Заказ собирается пошагово с подтверждением. Заявки сохраняются в SQLite, уведомления администратору повторяются при сбое. /revoke отзывает согласие на новые обращения. Портфолио не добавлено.

Администратор получает заказ или сообщение в личный чат с ботом. Чтобы ответить клиенту, используйте именно Reply / «Ответить» на полученную карточку или вложение. Поддерживается копирование текста, фото, документов и голосовых, если Telegram разрешает копирование конкретного сообщения. Ответ без Reply не выбирает произвольного клиента. /admin показывает число заявок. Сначала администратор должен открыть бота и нажать Start, иначе бот не сможет первым написать ему.

## GitHub → BotHost

1. Создайте репозиторий GitHub. Загрузите СОДЕРЖИМОЕ этой папки в корень: main.py, assets, documents, requirements.txt и остальные файлы. Не загружайте .env, рабочую базу и папку data. Токена в поставляемом проекте нет.
2. В bothost.ru создайте Python-бота, подключите URL репозитория и выберите нужную ветку. Главный файл: main.py. Python: 3.12 (минимум 3.10). requirements.txt не требует сторонних библиотек. При использовании Dockerfile стартовая команда уже указана; обычная команда — python main.py.
3. В ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ BotHost добавьте BOT_TOKEN (свой токен, не в GitHub), ADMIN_ID=7285144284, DATABASE_PATH=/app/data/korshun.sqlite3. Файл .env.example — только образец, бот не читает .env автоматически.
4. Постоянное хранилище /app/data должно быть включено. Запускайте одну копию бота. Сайт на REG.RU переносить на BotHost не требуется. Это отдельный процесс.
5. Запустите. Если ранее настроен webhook, приложение безопасно остановится с сообщением об этом: перед polling нужно осознанно убрать старый webhook через прежнюю конфигурацию бота. Другой polling-процесс также должен быть остановлен.
6. В личном Telegram администратора откройте @korshunbotsBOT и нажмите Start. С другого аккаунта пройдите согласие и тестовый заказ, затем проверьте Reply в обе стороны. Реальный запуск и API Telegram при разработке не выполнялись.

Документация платформы: https://bothost.ru/docs/getting-started и https://bothost.ru/docs/database-storage .

## Надёжность и хранение

Состояния диалогов, согласия, заявки и маршруты ответов переживают перезапуск. Делайте резервные копии /app/data через инструменты хостинга. Старые данные автоматически не удаляются: запросы на удаление обрабатываются оператором по почте, в том числе копии в Telegram. Бот не хранит полную историю свободного чата в SQLite.

Повторное нажатие «Отправить заявку» не создаёт второй заказ. При аварии между отправкой уведомления и отметкой в базе уведомление может повториться с тем же номером. Свободная переписка отправляется сразу: при сетевом сбое доставка может быть неопределённой, полной гарантии доставки чата нет. Если бот заблокирован клиентом, ответ отправить нельзя. Секретные чаты и служебные сообщения не поддерживаются. Ошибки логируются без токена и содержимого клиентских сообщений.

Сайт может продолжать отправлять свои уведомления через sendMessage с тем же токеном; он не должен запускать второй getUpdates-процесс. Заявки сайта и бота имеют отдельные базы.

## Проверки

python -m unittest discover -s tests -v

Пять автоматических сценариев с имитацией Telegram прошли: баннер/согласие/отзыв; заказ/дубликат/повтор уведомления; маршрутизация двух клиентов и запрет ответа после отзыва; сохранение этапа после перезапуска; ограничения административного сценария. Тесты не обращаются к Telegram и не отправляют реальные сообщения. Финальная проверка на BotHost с вашим токеном обязательна перед приёмом клиентов.
